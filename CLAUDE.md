# WorkOS Emulate

## Where documentation goes

`README.md` is the landing page: what the emulator is, install, quickstart, CLI flags, and links.
It stays short. Do not add sections to it.

Everything else lives under `docs/`:

- `docs/behavior.md`: production-parity notes, one `##` section per feature in the order of the
  `SUPPORTED.md` table. A change that makes a route accept or refuse what production does is
  documented here. An implemented feature with no section fails `bun run gen:supported`.
- `docs/seeding.md`: the seed file, and every feature that is seeded or configured through it.
- `docs/testing.md`: the Node API, other languages, webhooks and events, error hooks, interactive
  login pages.
- `docs/tokens.md`: JWT templates, signing key and issuer, OIDC discovery, redirect hosts.

When a change needs documenting, add a short section to the matching doc under the existing
heading for that feature. Prefer a table of code, condition and status over a paragraph of prose.

In `SUPPORTED.md`, the table between the `gen:supported` markers is generated by
`bun run gen:supported`; never edit that region by hand. The prose around it is hand-written, and
a feature's notes live in its `docs/behavior.md` section, which the table links to.
